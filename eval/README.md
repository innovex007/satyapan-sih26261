# Evaluation: reproducing the headline numbers

Everything here is measured on the **synthetic** dataset and **simulated** sources. The generator plants known defects and writes them to [`data/answer_key.json`](../data/answer_key.json); the evaluation runs the real pipeline output against that key.

| Number | Where it comes from |
|---|---|
| **51 / 51** planted defects found (10 defect types) | `evaluate.py`: every answer-key entry must have a matching finding of the same type on the same application (and document, where the defect is document-specific) |
| **0 false alarms** on clean applications | `evaluate.py`: findings raised on the 9 applications with no planted defect |
| **0 / 3** shared-land decoys flagged | `evaluate.py`: same village, different plot number |
| **9 / 9** twin photos, **0** false matches over 15,203 unplanted pairs | `twin_scan.py` / `evaluate.py` |
| **511 / 511** documents classified | `evaluate.py` |

Committed outputs from the last run: [`results.json`](results.json) (written by `evaluate.py`, read by the app's Evaluation page) and [`twin_results.json`](twin_results.json) (written by `twin_scan.py`). Re-running overwrites them.

## Reproduce from scratch (Windows, PowerShell, repo root)

```powershell
# 1. setup (once)
python -m venv backend\.venv
backend\.venv\Scripts\python -m pip install -r backend\requirements.txt

# 2. regenerate the dataset with the fixed seed, load the DB and run the pipeline (about 8 minutes on CPU)
backend\.venv\Scripts\python -m data.generator.seed --seed 42

# 3. score the pipeline against the answer key
$env:PYTHONIOENCODING = "utf-8"
backend\.venv\Scripts\python eval\evaluate.py

# 4. optional: the twin-photo margin (keypoint threshold 120; worst non-twin 83, hero re-shot 212)
backend\.venv\Scripts\python eval\twin_scan.py
```

Expected output of step 3 (abridged; the lines to check):

```
Planted defects found: 51/51   precision 0.895   recall 1.0
False alarms on the 9 clean applications: 0  (0.0 per 100 clean documents)
Unplanned findings on all applications: 6
Scanned-fact OCR accuracy: 81/82  (P 0.988 R 0.988 F1 0.988)
Text-layer fact accuracy:  1819/1819  (F1 1.000)
Classification: 511/511 (100.0%)
Twin detection: 9/9  ...  false matches on 15203 unplanted pairs: 0   threshold 120 (max non-twin 83, min re-shot 212)
Shared-land decoys flagged: 0/3
```

Notes:

- **Seed 42 matters.** The answer key, the application IDs (for example `EoA-DEMO-0417`) and the photo assignments are all derived from it. A different seed gives a different dataset and slightly different numbers.
- **Precision 0.895** is not a false-alarm rate. The 6 unplanned findings are all `CHK-FACULTY-01` (duplicate faculty ID), raised on the other institution of the three planted duplicate pairs (0104/0107, 0106/0117, 0109/0125); the finding is genuine, but the answer key does not list it separately. On the 9 clean applications there are none.
- **`data/answer_key.json` is regenerated by `seed`.** The committed copy is the one from seed 42, so you can diff your run against it. `data/mock_registry.json` (the simulated issuer/DigiLocker lookups) is also regenerated and stays git-ignored.
- **Scanned-fact OCR accuracy** (81 / 82) and **text-layer accuracy** (1819 / 1819) are printed by the same script. They depend on the installed RapidOCR model version, so the scanned figure can move by a fact or two on a different machine.
- Findings are re-created on every pipeline run, so finding IDs change between runs; the evaluation matches on type, application and document, not ID.
- Tests: `cd backend; .\.venv\Scripts\python -m pytest -q` checks that the generated data contains every planted defect type (5 tests).
